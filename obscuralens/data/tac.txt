# ObscuraLens curated IMEI TAC (Type Allocation Code) pack.
#
# Source: community TAC database maintained on GitHub (MoazEb/tac-database,
# itself compiled from public GSMA-certified device listings and imei.info
# records), sampled and spot-checked against well-documented assignments.
#
# This is a CURATED SUBSET (139 of ~255,000 known TACs) covering the iconic
# model families an OSINT operator meets most: every recent iPhone
# generation, Galaxy S/Note/Z/A lines, Pixels, Xiaomi/Redmi/POCO, Huawei,
# OnePlus, HMD Nokia, classic feature phones (Nokia N900, 3310), IoT modem
# modules (Quectel, Sierra Wireless) and rugged brands (Doogee, Ulefone).
# It is offline enrichment, not the complete registry.
#
# Format: one entry per line, sorted by TAC, no duplicates:
#   TAC8|Manufacturer|Model-hint
# where TAC8 is the 8-digit Type Allocation Code (the first 8 digits of an
# IMEI; digits 9-14 are the serial number and digit 15 the Luhn check digit).
#
# Reporting Body Identifier (first two TAC digits, 3GPP TS 23.003):
#   01 = PTCRB (North America)         35 = BABT (United Kingdom)
#   86 = TAF (China)                   91 = TEC (India, domestic makers)
#   44 = BABT-era secondary range (Motorola / Nokia / Siemens era devices)
#   99 = modern mixed allocation (CDMA-era iPhones, current Chinese makers)
# Other two-digit codes (33, 49, 50, 51, 52, 98, ...) are GSMA-assigned
# regional certification identifiers whose public documentation is
# inconsistent; the tracker reports the raw code and only names the bodies
# listed above.
#
# Notes:
# * A miss here means "not in this curated subset", NOT "unknown device" -
#   hundreds of thousands of TACs exist and only commercial IMEI services
#   can resolve them all.
# * The imei_math source derives TAC / reporting body / SNR / check digit /
#   Luhn validity from the identifier itself, so basic decomposition works
#   for any IMEI even without a TAC pack hit.
