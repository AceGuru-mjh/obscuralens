# Internationalization (i18n)

ObscuraLens ships a small, dependency-free translation runtime under
`obscuralens/i18n` with catalogues for **14 languages** at 100% key
coverage. It exists so the console UI, the desktop launcher and future
front-ends can speak the analyst's language without pulling in gettext,
`.mo` compilation steps or third-party i18n frameworks.

The design choice that shapes everything else: **catalogues are Python
modules, not data files.** Every locale under `obscuralens/i18n/locales`
defines a `STRINGS` dict mapping flat dotted keys (`"app.title"`,
`"errors.timeout"`, `"plural.results.many"`) to translated values. Because
the catalogues are code, they work unchanged inside the frozen desktop
executable (no gettext binaries, no file I/O at translation time), stay
greppable and diff-friendly, and load once at import.

The runtime is standard-library only and never raises on bad input: a
missing translation degrades to readable text, not an exception.

## Catalogue layout

The English source catalogue (220 keys) is organised in flat namespaces;
every locale mirrors them exactly:

| Namespace | Keys | Example entries |
|---|---|---|
| `app.*` | 10 | `app.title`, `app.version` ("Version {version}"), `app.channel`, `app.edition` ("Desktop edition") |
| `common.*` | 63 | `common.ok`, `common.results`, generic buttons, status words, shared column labels |
| `menu.*` | 20 | `menu.choose_option` ("Choose an option:"), the interactive-console prompts |
| `cli.*` | 28 | `cli.usage_hint` ("Usage: obscuralens <command> [options]"), `cli.starting_lookup` ("Looking up {target} ({kind})..."), `cli.sources_failed` ("{count} source(s) failed to respond.") |
| `kinds.*` | 18 | `kinds.ip` ... `kinds.coords` (the 14 kind names), `kinds.detected_kind` ("Detected kind: {kind}") |
| `errors.*` | 20 | `errors.timeout` ("Request to {source} timed out after {seconds}s."), `errors.rate_limited` |
| `report.*` | 20 | `report.title` ("Investigation report"), `report.generated`, `report.disclaimer` (the report disclaimer text) |
| `desktop.*` | 29 | `desktop.listening_on` ("Listening on http://{host}:{port}"), `desktop.single_instance`, `desktop.checking_updates` |
| `plural.*` | 12 | four triples (`results`, `sources`, `findings`, `matches`) with `.zero` / `.one` / `.many` suffixes |

Keys are flat strings -- `"cli.starting_lookup"` is one dict key, not a
nested structure -- which keeps grepping, diffing and parity testing
trivial.

## Supported languages

| Code | English name | Native name | Direction |
|---|---|---|---|
| `en` | English | English | ltr |
| `zh` | Chinese (Simplified) | 简体中文 | ltr |
| `ja` | Japanese | 日本語 | ltr |
| `ko` | Korean | 한국어 | ltr |
| `de` | German | Deutsch | ltr |
| `fr` | French | Français | ltr |
| `es` | Spanish | Español | ltr |
| `pt` | Portuguese (Brazil) | Português (Brasil) | ltr |
| `ru` | Russian | Русский | ltr |
| `it` | Italian | Italiano | ltr |
| `nl` | Dutch | Nederlands | ltr |
| `pl` | Polish | Polski | ltr |
| `ar` | Arabic | العربية | rtl |
| `hi` | Hindi | हिन्दी | ltr |

Every catalogue defines the same key set as `en` (the source catalogue,
currently 220 keys); the test suite enforces key-set parity, placeholder
parity and completeness, so a shipped locale is either complete or absent.
`list_languages()` reports `completion` per locale -- always `1.0` for the
shipped set, by construction.

Regional variants resolve to their primary language: `zh-CN` -> `zh`,
`pt-BR` -> `pt`, `EN-gb` -> `en`. Only `ar` renders right-to-left
(`is_rtl("ar")` is `True`); everything else is ltr.

## Using it from Python

```python
from obscuralens.i18n import set_language, t, tp, get_language

set_language("de")                          # -> "de" (the activated code)
t("app.version", version="5.1.0")           # "Version 5.1.0"
t("menu.choose_option")                     # "Option wählen:"
t("errors.timeout", source="ipwho.is", seconds=10)
# "Anfrage an ipwho.is nach 10s abgebrochen (Timeout)."

set_language("zh")
t("app.version", version="5.1.0")           # "版本 {version}" -> "版本 5.1.0"
get_language()                              # "zh"
```

`set_language` normalises and validates the code: `set_language("JA")`
activates and returns `"ja"`; an unknown code raises
`UnknownLanguageError` (a `ValueError` subclass whose message lists the
available codes) *before* any state changes, so a failed call never
disturbs the previously selected language. Until the first successful
`set_language` call -- and again after `reset()` -- the module is in its
default English state.

Module-level state, honestly: the active language is one module global,
not thread-local storage. A process has one active language at a time;
if two threads fight over `set_language`, last write wins. For
per-request language selection in a server, resolve the locale yourself
(`best_match`) and use `get_translation(code).format(...)` instead of
the module-level `t()` -- the `Translation` wrapper is stateless.

### The fallback chain

`t()` resolves a key through: **current language -> English -> caller
default -> the key itself**. Consequences:

- a key missing from the active locale falls back to its English value;
- a key missing everywhere becomes the `default=` argument when given;
- without a default, the key itself is returned (and interpolated), so
  `t("no.such", what="x")` returns `"no.such"` -- readable junk, never an
  exception.

The same chain applies to `tp()`, which additionally falls back to the
bare key when no plural form exists.

### Interpolation rules

Placeholders are `{name}` tokens. During interpolation:

- a token whose name is a supplied keyword is replaced by `str(value)`;
- tokens without a matching keyword stay **literal**
  (`t("app.version")` -> `"Version {version}"`);
- extra keyword arguments are ignored -- callers may pass a superset;
- brace pairs that do not name anything (JSON snippets in help text)
  survive verbatim;
- the call never raises on any combination of template and kwargs.

### Plural rules

`tp(key, count)` picks `key.zero` for `count == 0`, `key.one` for
`count == 1` and `key.many` otherwise (negative counts use the `many`
form -- a simplification, documented as such; Slavic-style multi-form
plurals are out of scope for this runtime). `{count}` is interpolated
automatically, and an explicit `count=` keyword would override it:

```python
from obscuralens.i18n import set_language, tp

set_language("de")
tp("plural.results", 0)     # "Keine Ergebnisse"
tp("plural.results", 1)     # "1 Ergebnis"
tp("plural.results", 5)     # "5 Ergebnisse"

set_language("ru")
tp("plural.results", 5)     # "Всего результатов: 5"
tp("plural.results", -3)    # the .many form with count=-3
```

Keys without dedicated plural forms simply interpolate `{count}` into
their single value.

## Accept-Language integration

`best_match(header)` picks the best supported locale for an HTTP
`Accept-Language` header with plain string operations -- no dependencies:

```python
from obscuralens.i18n import best_match, set_language

best_match("zh-CN,zh;q=0.9,en;q=0.8")   # "zh"  (regional tag -> primary)
best_match("de;q=0.3,fr;q=0.9")         # "fr"  (quality values decide)
best_match("sv,da;q=0.9")               # "en"  (no match -> default)
best_match("*;q=0.5,en;q=0.8")          # "en"  (* matches the default)
best_match(None)                        # "en"
```

Parsing rules: entries are split on `,`; `;q=` parameters set the quality
(default 1.0, unparseable/negative/zero values are dropped or defaulted);
entries are ranked by quality with ties keeping header order; a tag
matches when it equals a locale code or when its primary subtag does;
`*` matches the default language. The result is a locale code suitable
for `set_language` directly:

```python
set_language(best_match(request_headers.get("accept-language")))
```

## Catalogue introspection

```python
from obscuralens.i18n import list_languages, language_name, is_rtl, available_locales

for info in list_languages():          # SUPPORTED_LANGUAGES order
    print(info.code, info.english_name, info.native_name,
          info.direction, info.completion)

language_name("de")                    # "Deutsch"
language_name("pt-BR")                 # "Português (Brasil)"
language_name("xx")                    # "xx" (unknown codes pass through)
is_rtl("ar")                           # True
available_locales()                    # ['en', 'zh', ...] registry order
```

`LanguageInfo` is a frozen dataclass: `code`, `english_name`,
`native_name`, `direction` (`"ltr"`/`"rtl"`) and `completion` (0.0-1.0,
key count over the English key count, capped at 1.0).

For direct catalogue access, `get_translation("de")` returns a cached
`Translation` wrapper with a mapping-like protocol:

```python
from obscuralens.i18n import get_translation

de = get_translation("de")
"app.version" in de            # True
len(de)                        # key count (220 for shipped locales)
de.get("app.version")          # raw value, placeholders left literal
de.format("app.version", version="5.1.0")   # translated + interpolated
de.has("no.such.key")          # False
list(de.keys())[:3]            # first catalogue keys
```

Unknown codes raise `UnknownLanguageError`; `Translation` can also be
constructed directly around any `Dict[str, str]` for tests and partial
catalogues.

## Adding a language

1. **Copy the source catalogue.** Copy `obscuralens/i18n/locales/en.py`
   to `<code>.py` (two-letter, lowercase code). Keep the module-level
   docstring block and translate it (language, native name, direction,
   locale code, translators).
2. **Translate every key.** All of them -- the parity tests fail on a
   partial catalogue by design. Keep the flat `"prefix.key": "value"`
   layout so diffs stay readable.
3. **Keep `{placeholders}` verbatim.** `tp()` additionally requires the
   `.zero` / `.one` / `.many` triple to keep `{count}`. The placeholder
   parity test extracts every `{token}` from each value and compares the
   set against English -- a dropped or renamed placeholder fails the
   suite.
4. **Register the module.** In `obscuralens/i18n/locales/__init__.py`,
   import the module and add `"code": code.STRINGS` to the `LOCALES`
   dict. The registry performs a defensive check that every catalogue is
   a `str -> str` mapping, so a module accidentally exporting the wrong
   object fails at import, loudly.
5. **Add the metadata.** In `obscuralens/i18n/__init__.py`, append the
   code to `SUPPORTED_LANGUAGES` and add a
   `(english_name, native_name, direction)` entry to `_LANGUAGE_META`.
   `"rtl"` is the only direction value with an effect today.
6. **Run the tests.**

   ```bash
   python -m pytest tests/test_i18n.py -q
   ```

   The suite is offline and covers key-set parity, placeholder parity,
   plural behaviour, fallback chains and `best_match` negotiation for
   every registered locale automatically.

There is no compile step, no tooling and no ordering requirement beyond
the registry edit -- the moment the module is imported, the language is
usable through `set_language`, `t`, `tp` and `best_match`.

## Testing notes

- **Key-set parity:** every locale must define exactly the English key
  set -- no missing keys, no extras. A partial translation is a bug the
  suite catches before review.
- **Placeholder parity:** for every key, the set of `{placeholder}` tokens
  in the translated value must equal the set in the English value.
  Interpolation never raises regardless, so this is a content-quality
  test, not a crash-prevention one.
- **Runtime behaviour tests** exercise the fallback chain, unknown-code
  handling (`UnknownLanguageError`), the `Translation` protocol, plural
  selection including negative counts, and `Accept-Language` negotiation
  including quality values, `*`, garbage entries and empty input.
- Everything is offline; the catalogues are imported once per test
  session.

## Limitations, honestly

- Three plural forms only (`zero`/`one`/`many`); languages with richer
  plural systems (Polish and Russian are shipped) approximate with the
  `many` form.
- No message-context support (the same English string used with two
  meanings shares one translation).
- Regional variants collapse to primary locales; there is exactly one
  Chinese (Simplified) and one Portuguese (Brazilian) catalogue.
- The catalogues are only as current as the last translation pass; new
  UI strings land in English first and the parity tests then fail for
  every other locale until translators catch up -- which is the intended
  pressure valve.
